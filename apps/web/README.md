# Local React workspace

This Next.js interface extends the existing Python MVP. Research operations stay in
`src/mvp`; this directory renders projections and forwards allowlisted HTTP routes.
Streamlit remains available as a separate interface.

## Setup and start

Use Node.js 20.9 or later and pnpm. The tested local runtime is Node 24.19.0;
dependencies are pinned in `package.json` and `pnpm-lock.yaml`. No frontend command
downloads embedding models or calls PubMed.

From the repository root, install the optional Python web group in a separate
virtual environment, then the locked JavaScript group:

```sh
python3 -m venv .venv-web
.venv-web/bin/python -m pip install -r requirements-web-dev.txt
cd apps/web
pnpm install --frozen-lockfile --ignore-scripts
cd ../..
.venv-web/bin/python scripts/run_web.py --data-dir .mvp-web-state
```

Open **http://127.0.0.1:3000**. Use that exact origin consistently; `localhost` is a
different session origin and is rejected. Both servers bind to loopback. Ctrl-C
in the launcher terminal stops both children. Keep the same data directory and
browser cookie to reopen work after restart. Do not run a live Streamlit provider
process alongside the API as though they shared its process-local rate gate.

For a production-mode local check, first build and then use `--production`:

```sh
cd apps/web
NEXT_TELEMETRY_DISABLED=1 pnpm build
cd ../..
.venv-web/bin/python scripts/run_web.py --production --data-dir .mvp-web-state
```

The launcher supplies `MVP_API_ORIGIN` and `MVP_WEB_ORIGIN`. The bridge accepts only
fixed HTTP `127.0.0.1` origins. It does not accept arbitrary upstream URLs, redirects,
unsupported routes, unsupported query parameters, or mutation bodies over 1 MiB.
Backend origin/CSRF/session checks remain authoritative.

## Reopening, drafts and operation retries

The Python boundary retains workspace access credentials in its private local
registry. The browser receives an opaque HttpOnly session cookie. No workspace
capability is stored in URLs, JavaScript state, browser storage, or exports.
Clearing/expiring the cookie loses its access; this does not recover lost v0.1
workspace handles or provide cross-device or named-user authentication.

Question/query controls, pending source selection, evidence question, and assessment
forms use server-side versioned drafts. A short debounce saves edits; screen
navigation drains a pending save before leaving. Assessment submission holds
navigation until its acknowledged new-head draft baseline is persisted, including
an immediate screen change after revision. Failed saves and CAS conflicts
retain edits, block normal navigation, and require explicit retry. Drafts and
committed immutable assessments are separate. An explicit revision loads the latest
assessment. Source inspection alone never searches, prepares, or saves a judgment.

Only pending operation request IDs and SHA-256 payload fingerprints enter
`sessionStorage`. After ambiguous response loss, an identical submission reuses its
request ID. Explicit refresh creates a new operation. Acknowledged workspace creation
clears its pending key so another intentional workspace is distinct.

## Development checks

```sh
cd apps/web
pnpm typecheck
pnpm test
NEXT_TELEMETRY_DISABLED=1 pnpm build
```

The hook tests exercise delayed autosave, navigation flush, retained edits on 409,
and stale nullable assessment heads using actual React hooks with mocked HTTP.
`react-test-renderer` emits its upstream deprecation warning; these checks are not
browser coverage. Record actual browser checks separately.

Regenerate the API contract after Python response-model changes:

```sh
.venv-web/bin/python scripts/export_web_openapi.py
cd apps/web
pnpm generate:api
pnpm typecheck
```

`lib/openapi.json` is exported from FastAPI. `lib/generated-api.ts` is generated by
`openapi-typescript`; do not maintain duplicate research interfaces by hand.

## Presentation and source integrity

`app/layout.tsx` imports `../../streamlit/theme/tokens.css` from the shared apps tree.
The exact portable palette and type tokens remain the single identity source;
`app/globals.css` is only the React presentation adapter. On desktop, a passage and
its judgment share a CSS grid row. On narrow screens each passage precedes its
matching judgment. The source inspector follows the complete paired list.

React text nodes escape source text. `highlightParts` converts canonical Unicode
code-point offsets with `Array.from` before slicing, including astral characters,
combining marks, and markup text. Current and historical inspectors bind to their
original saved search and preparation; archived runs are read-only in this UI.
Outbound citation/source links use a fixed provider-host allowlist.

## Semantic exploration

The map represents exactly one immutable saved search, including all its bounded
preview records rather than only the selected source papers. Opening Discover reads
the map listing and existing coordinates. Only **Build map**, **Explicitly rebuild**,
or **Retry map build as a new artifact** submits computation. The optional pinned
local embedding profile must be explicitly installed/configured first; missing setup
disables builds while preserving list/evidence features and existing saved maps.
See the repository v0.2 guide for the implemented model setup and worker commands.

Saved maps have distinct IDs, manifests and coordinate hashes. The chosen map ID may
appear in the URL; it is not a workspace capability. Filtering hides map points and
paper rows using stable paper IDs. Panning, zooming, selection and navigation never
refit a projection or request discovery. SVG points and the complete keyboard paper
list open the same inspector. On small screens, Map/Papers buttons switch visibility
while keeping both panels mounted; the inspector remains outside the panels and
available from either view. Switching panels retains map pan/zoom and never refetches
or refits the map. Desktop displays both panels. Source selection remains a separate server draft;
inspection does not prepare sources. Similar papers are fetched from the map's
original-space cosine endpoint, not inferred from screen distance.

The UI displays map job attempts, processed counts and errors, polls only active
persisted jobs, and offers explicit cooperative cancellation. A failed/cancelled job
can be explicitly retried as a new artifact. Switching searches does not reassign a
running job or publish it into another search. Older maps remain selectable. A
single-paper saved example shows a single point and no invented neighbors; identical
coordinates overlap without jitter. Synthetic coordinates exist only in clearly
labeled software tests.

The local web UI is not a deployed service. Mocked frontend tests, real local embedding
checks, and live PubMed checks have different evidential meaning and must be reported
separately. None establishes scientific usefulness or exhaustive literature capture.
