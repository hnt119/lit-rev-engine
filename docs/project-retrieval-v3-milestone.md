## I9 candidate interface

Add only optional `method="bm25_context_blocks"` to `ReviewStore.search_sources` and `retrieve-sources --method`. The stable default remains `bm25`; all existing method traces and behavior remain identical. The new version is `lit-rev-engine.project-retrieval.v3.bm25_context_blocks`. No model, network, settings, query/article/answer hardcoding, clinical vocabulary, heading boost or automatic finding.

Each selected nonblank canonical block supplies exactly one candidate. Its own anchor is the complete original block: start=0, end=len(text), quote=text, preserving leading/trailing whitespace and original Unicode/newlines. Skip only whitespace-only blocks. No window splitting, block stitching, quote normalization, text truncation or output word cap. This applies to retained TXT blocks, actual PDF page blocks and accepted JATS title/paragraph/table blocks. These are explicit reviewer-facing source candidates; long blocks do not become model inputs automatically.

Retain v1 casefolded Unicode tokenizer, exact stop words, distinct sorted query tokens, BM25 k1=1.2, b=0.75 and positive-log IDF. Retain the exact v2 nearest preceding accepted XML paragraph of the same immediate parent and last-80-word context rule. Each scoring representation contains complete own-block tokens plus context tokens exactly once; DF, N, lengths and average use these representations. Context is empty for TXT/PDF/titles/no eligible preceding paragraph. The existing positive-score filter and report/block order ties remain deterministic. Candidate parameters contain tokenizer_id, sorted stop_words, k1, b, context_rule, context_max_words and **passage_unit="block"**; omit window_words/overlap_words for this method.

Each passage preserves the existing own anchor, typed locator, document/source/parser hashes, current eligibility and manual study-link provenance, plus the v2 separate `scoring_context` list. Context cannot count as own quotation support. Project/current-document/scope isolation, selected-source corruption/current-identifier rejection, read-only behavior and one SQLite snapshot remain unchanged. A large complete block is inspectable source text, not an assertion of clinical support.

Implementation owns src/review/retrieval.py, necessary src/review/cli.py choices and tests/test_project_retrieval.py. Check literal whole-block BM25 math, full long tables/paragraphs, exact padded TXT and actual PDF page bounds, skipped blank blocks, context once, all current-source/integrity/snapshot guarantees and identical original method traces. No new gold inspection or medical ranking.
