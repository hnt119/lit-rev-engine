# Native distribution evidence and remaining deliverables

This is an engineering attribution/source review, not a legal certification. Original engine code remains MIT. Other components retain their upstream terms. It neither changes nor retroactively qualifies the immutable `34f61ec` candidates or optional-library capsule v2. New notice inputs below are source changes for a later rebuilt candidate.

## Prepared source evidence

`apps/desktop/notices/native/MANIFEST.json` binds 197 input files (about 1.1 MB), including exact retained notices. `SOURCE_EVIDENCE.json` records primary-source identities and remaining deliverables. The build-only `copy_native_source_evidence(resources / 'NATIVE_DEPENDENCY_NOTICES')` verifies the complete closure before and after copying; it never downloads or executes source. A final scan distinguishes **bundled verified** notices from **external audit evidence not bundled**. An external audit folder must not be described as already shipped.

- **Electron 45.0.0:** its [exact DEPS](https://github.com/electron/electron/blob/v45.0.0/DEPS) declares Chromium `156.0.8078.48` and Node `24.22.0`. Retained DEPS, patch map, one FFmpeg patch, build arguments and Electron MIT notice are hash-bound. These identify upstream build inputs; they do not reconstruct every credited library's binary linkage.
- **Next 16.4.2 compiled modules:** the retained official [Next source manifest](https://github.com/vercel/next.js/blob/v16.4.2/packages/next/package.json) provides source-declared dependency pins. The scanner reports them as hints beside the actual bundled metadata hash. It does not fabricate a missing bundled version or turn unknown labels into a blanket publication blocker. Existing five reviewed supplemental web notices remain intact; upstream `client-only` and unused sharp/libvips were already omitted/replaced in the candidate as documented separately.
- **pydantic_core 2.46.4:** the [official release metadata](https://pypi.org/pypi/pydantic_core/2.46.4/json) points to the pydantic monorepo; the old standalone-repository tag is not the correct source. Its exact source archive SHA-256 is `62f875393d7f270851f20523dd2e29f082bcc82292d66db2b64ea71f64b6e1c1`. Retained Cargo files and 183 notice files cover its 103 checksum-pinned registry dependencies. Two license fallbacks use the exact crate's upstream identity: r-efi's published AUTHORS contains its permissions; wit-bindgen-rt's exact crate VCS commit supplies three root license texts. This is a lockfile attribution superset, including target/build/dev possibilities; it does not assert all crates are linked or select one upstream license alternative for the owner.
- **Python build inputs:** a projection from [the release's pinned build manifest](https://github.com/astral-sh/python-build-standalone/blob/0c5e581b54a4736cdbbe68bdd6d7e571a1dca11e/pythonbuild/downloads.json) records declared dependency versions, source URLs and checksums. Actual retained PYTHON provenance, linked-library declarations, notices and binary hashes remain separate. A declared build version is not a new execution measurement.

The native scanner now associates actual files with each installed wheel's RECORD. It includes pywin32 and pip's vendored launchers rather than reviewing only a fixed package-name list. Original RECORD hashes and final payload hashes remain distinct; signing can change bytes, and mismatches need the recorded build/signature context rather than an automatic equivalence claim. Native files without wheel records still include Electron, CPython and their linked libraries; they are not silently discarded.

## Validation boundary

Fresh inspection of the original Windows candidate identifies native RECORD ownership for pip, pydantic_core and pywin32, without modifying it. This is an attribution/integrity check, not execution of Windows, models, providers or scientific review. Original candidate hashes, original SBOM sidecars and capsule recipe stay unchanged. Source changes require the integration owner's review and a new clean source binding before rebuild.
