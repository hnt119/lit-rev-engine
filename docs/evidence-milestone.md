# Source-anchored evidence milestone

Status: I6a source documents accepted and committed in 3c2af01 after 68 independent acceptance cases, 47 implementation cases and 731 clean staged regression passes. I6b ledger APIs/exports accepted after 81 independent cases and 42 implementation cases. I6c CLI accepted after 86 independent cases and 25 implementation cases. The coordinator reviewed literal state truth, hashes, identity enrichment, durable source/CLI behavior and export snapshots; the eight-block offline guide passed with network/model guards. The evidence gate stores human-entered structured findings and appraisal judgments with verifiable source quotations. It does not infer clinical findings, pool effects, score risk of bias automatically, or treat a citation label as evidence support.

## Architecture decisions

Keep source parsing/version storage in `src/review/documents.py` and extraction/reviewer state in `src/review/evidence.py`; ReviewStore exposes their public APIs. Source bytes are durable SQLite artifacts, not filesystem pointers. Parsed source blocks carry stable version-specific IDs and typed locators: actual one-based PDF positions, XML paragraph/table paths, or plain-text blocks. XML paragraphs must never be labeled PDF pages. Retain parser identity/version and exact source hash, alongside canonical block text and character offsets.

Supported source adapters will be frozen separately: UTF-8 text and publisher article XML use the standard library; PDF extraction lazily uses the existing PyMuPDF dependency. No model/settings/dotenv/network initialization. Every source attachment is a new immutable version with reviewer/reason; old bytes/blocks remain retained. Replacing a report's active document makes earlier extraction verification stale until a new revision is anchored to the new version and independently checked.

Source parsing must be deterministic from the very same byte snapshot that is hashed/stored. Quote anchors identify document/version/block, half-open character offsets, and the exact substring. Validate nonempty exact quotation against canonical block text, bounds, and matching report/project. Preserve table/section locators and describe text normalization; automatic quote validation proves location, not entailment of the value.

## Structured extraction and verification

Each manual extraction has a stable ID and append-only proposal revisions. Its current revision identifies report, linked study, active source version, field, finite JSON value, context (population, comparison, outcome, timepoint, analysis, units and notes as applicable), source anchor, author and reason. A revision can correct values/context/anchors and always invalidates earlier verification. Report/study ownership and current full-text inclusion are checked; conflicted/missing study links cannot supply a verified study-level result.

For design-appropriate appraisal, use a separate explicit extraction kind with user-selected instrument name/version and domain. Preserve the domain judgment and supporting quotation/reason; instrument choice and application remain review-protocol inputs. Do not silently substitute an appraisal tool or compute an overall quality score. This supports auditable judgments without claiming a validated automated appraisal system.

Verification is append-only and refers to an exact current revision ID. A distinct reviewer can confirm or reject it with a reason. Latest vote per verifier determines agreement/conflict; no majority vote or automatic union. An explicit adjudication can resolve existing verification reviews with a named reviewer/reason, and subsequent reviews invalidate it. The current revision's author cannot confirm/adjudicate their own proposal. Source changes or proposal revisions prevent an earlier confirmation from certifying new content.

Current states must distinguish proposal, confirmed, rejected, conflict, stale source, and no longer eligible/linked. Verified exports contain only current confirmed revisions with valid source/eligibility/linkage dependencies; proposals and unresolved/rejected/stale content remain visible in audit exports. Source quotation support still requires reviewer judgment. Duplicate extraction slots and cross-report disagreement must remain visible rather than being silently pooled or merged.

## I6a source-document contract, accepted

Implementation owns `src/review/documents.py`, necessary ReviewStore/exporter delegations, and `tests/test_review_documents.py`. Retrieval supplies independent synthetic source fixtures and metadata under `tests/fixtures/evidence/`; Evaluation owns `tests/test_review_documents_acceptance.py`. No evidence proposals, verification, or CLI in this first source ticket.

`parse_source_bytes(content, format) -> {"parser_id": str, "parser_metadata": dict, "blocks": list, "source_identifiers": dict}` accepts nonempty bytes and exactly `txt`, `jats_xml`, or `pdf`. Parse the supplied bytes once without file calls; failures are contextual ValueError and leave no ledger data. Parser identity is versioned per format (`lit-rev-engine.source.v1.txt`, `.jats_xml`, `.pdf`); parser_metadata records Python version plus effective decoding/normalization/extraction options, and PyMuPDF version for PDF. TXT decodes UTF-8/BOM and retains exact decoded text as one block with ID `text:1`, locator `{"type":"text_block","ordinal":1}`. Reject empty/whitespace-only source content.

Frozen parser_metadata keys: all formats include `python_version` from the current interpreter. TXT adds `encoding="utf-8-sig"` and `normalization="none"`. JATS adds `normalization="xml-whitespace-v1"`, `tables="rows-tab-separated-v1"`, `external_dtd="ignored"`, and `entities="rejected"`. PDF adds `pymupdf_version` (PyMuPDF VersionBind), `sort=true`, and `normalization="none"`. Runtime version values are captured provenance, not hard-coded benchmark assumptions.

The parser result also includes `source_identifiers`: `{}` for TXT/PDF; normalized DOI/PMID entries only when explicitly present in JATS's own `front/article-meta/article-id` with pub-id-type doi/pmid. Use the accepted identity normalizers, reject invalid/conflicting repeated own IDs, and never take cited-reference IDs. Attachment rejects a source DOI/PMID contradicting an already known canonical report ID of the same type. Preserve source_identifiers in document metadata/CSV. Missing identifiers remain unknown; do not guess identity from PDF text or title similarity. The reviewer still establishes the source/report association when an automated identifier comparison is unavailable.

PDF uses lazy PyMuPDF from bytes and sorted page text, one block for each actual PDF page (including blank pages), ID `pdf:page:N`, locator `{"type":"pdf_page","page":N}`. Do not run RAG settings, chunking, or models. Reject corrupt/encrypted/unreadable/all-text-empty documents; no OCR or password guessing. Report one-based PDF positions, not printed journal page numbers. Canonical PDF block text is the extracted text, without further whitespace rewriting.

JATS XML requires article root; reject declared entities/error/malformed XML and make no external DTD/network calls. Extract the main article's title, abstract/body paragraphs, and complete body table-wrap blocks in document order. Skip selected table descendants as standalone paragraphs to avoid duplicating table content. Exclude reference lists and sub-article branches (including peer-review/editorial correspondence) from finding blocks while retaining their original source bytes. Stable IDs are `xml:` plus a structural path of local tag names with one-based sibling indices, e.g. `/article[1]/body[1]/sec[1]/p[1]`. Locator fields are `type="xml_element"`, `path`, `tag`, optional original `element_id`, `section_title` (nearest enclosing section title), and `table_label`. Canonical mixed paragraph text collapses whitespace after concatenating inline text, preserving meaningful punctuation/Unicode. Table text consists of nonempty lines for label, caption, every table row (cells separated by tabs), then table-wrap-foot text; lines are separated by newlines. Cell/caption/foot text uses the same inline whitespace normalization. It does not infer values from images or spanning-cell semantics. Document the transformation and retain exact XML bytes. Every block has `id`, one-based `ordinal`, `text`, and `locator`; IDs are unique within a document version. Require at least one nonempty extractable block.

`ReviewStore.attach_document(project_id, record_id, content, format, reviewer, reason, *, filename=None, source_url="", version_label="") -> dict` creates a new immutable source version for an existing report, independent of screening status. Nonempty reviewer/reason required. Filename defaults to source.txt/source.xml/source.pdf, and must be a safe single basename (no separators, traversal, or control characters); URL/version label are retained strings and never fetched/inferred. Parse/hash/store the same bytes transactionally. Return metadata `id`, `project_id`, `record_id`, integer `version` (per-report creation sequence, not a publisher version), `format`, `filename`, `source_url`, `version_label`, `source_sha256`, `size_bytes`, `parser_id`, `parser_metadata`, `source_identifiers`, `blocks_sha256`, `block_count`, `reviewer`, `reason`, `created_at`, `active=true`. Repeated attachment makes a new version even for identical bytes; it is an explicit provenance revision, not a keyed import.

## I6b structured evidence contract, accepted

Keep this ticket limited to ledger APIs and exports in `src/review/evidence.py`, necessary ReviewStore/exporter delegations, and `tests/test_review_evidence.py`; CLI belongs to I6c. Evaluation owns `tests/test_review_evidence_acceptance.py` and the E6b evidence report. Retrieval supplies independent invented extraction/context/appraisal truth under `tests/fixtures/evidence/extractions.json` without changing pinned sources. No model, network, live data, or Git operations.

The APIs are `propose_evidence(project_id, record_id, study_id, document_id, field, value, context, anchor, reviewer, reason, *, kind="finding", appraisal=None)` and `revise_evidence(project_id, evidence_id, study_id, document_id, field, value, context, anchor, reviewer, reason, *, appraisal=None)`. A proposal creates a stable evidence ID and revision ID. A revision keeps its report and kind, supplies a complete replacement payload, and creates a new revision ID and integer revision number. Never overwrite an earlier revision or merge duplicate fields. Both APIs return the immutable revision with `id`, `evidence_id`, `project_id`, `record_id`, `revision`, `kind`, `study_id`, `document_id`, `field`, `value`, `context`, `anchor`, `appraisal`, `source_sha256`, `blocks_sha256`, `reviewer`, `reason`, `created_at`, and `revision_sha256`. The revision hash covers the compact sorted-key finite UTF-8 JSON of the complete public revision except the hash itself, using the same canonical encoding as source blocks. It detects accidental payload changes; consistently rewriting data/hashes is outside the unsigned-ledger guarantee.

Values are finite JSON; context is a finite JSON object with only `population`, `comparison`, `outcome`, `timepoint`, `analysis`, `units`, and `notes` keys (all optional). Reviewer, reason and field are nonempty strings. Kind is exactly finding or appraisal. Findings require appraisal=None. Appraisals require a nonempty string value for the entered judgment and an exact object containing nonempty `instrument`, `instrument_version`, and `domain` strings; these are protocol inputs, not validated clinical instruments or automatic scores.

Input anchor is exactly `block_id`, integer `start`, integer `end`, and nonempty `quote`. Offsets are Unicode code points with half-open bounds; reject booleans, whitespace-only quotations, invalid bounds, mismatched substrings, or wrong project/report/document. The stored anchor additionally records the original block locator. Proposals/revisions require current full-text inclusion, resolved linkage containing the requested study, and the report's active document, checked under the same write transaction. Store hashes from the verified document bytes/blocks, never from caller metadata.

The verification APIs are `review_evidence(project_id, revision_id, decision, reviewer, reason)` and `adjudicate_evidence(project_id, revision_id, decision, reviewer, reason)`, with decision exactly confirm or reject. Both create events with `id`, `project_id`, `evidence_id`, `revision_id`, `decision`, `reviewer`, `reason`, `kind` (review/adjudication), and `created_at`. Require a current revision with valid current source/eligibility/linkage dependencies; reviewer must differ exactly from that revision's author for either decision and adjudication. Named strings are declared identities, not authenticated accounts. Adjudication requires an existing review of that exact revision. Latest vote per reviewer determines exactly proposed/confirmed/rejected/conflict; an adjudication after all reviews controls the result, and any later review invalidates it. No quorum or majority is inferred.

The read APIs are `list_evidence(project_id, record_id=None, *, verified_only=False)`, `list_evidence_revisions(project_id, evidence_id=None)`, and `list_evidence_reviews(project_id, evidence_id=None)`. Current rows contain `evidence_id`, `project_id`, `record_id`, `current_revision`, `verification_state`, `dependency_issues`, `state`, `verified`, and `active_verification_event_ids`. Dependency issues have a fixed order: stale_source, source_identity_conflict, ineligible_report, unresolved_linkage, study_not_linked. Compare retained source_identifiers with the report's current canonical DOI/PMID; a same-type contradiction is source_identity_conflict even when that bibliography identifier was unknown at attachment. Pending/unlinked/conflicted linkage is unresolved_linkage; a resolved association that omits the requested study is study_not_linked. State is the first dependency issue, otherwise verification_state. All reads use one snapshot, validate ownership/unknown IDs, revision hashes, anchors, and retained source/block integrity. Source replacement always leaves earlier document IDs stale, even with identical bytes. Current screening/linkage requirements are conditional: restoring the same eligibility/study association can restore a current confirmation, while its audit history remains unchanged.

Coordinator reproduced the source-identity case before E6b: attach DOI X/PMID 123 while the report's PMID is unknown, then import a same-DOI record supplying PMID 124. Bibliography enrichment and original sources remain retained, but this active source cannot supply verified evidence. The dependency check addresses that concrete gap without forcing the source identifier into bibliography metadata or blocking its later import.

When evidence exists, the normal project export additionally includes `evidence` (current rows), `evidence_revisions`, `evidence_reviews`, and `verified_evidence` (current verified rows), plus evidence.csv, evidence_revisions.csv, evidence_reviews.csv, verified_evidence.csv, and verified_evidence.json. Current-row CSVs flatten current_revision and append the current state/verification/dependency fields; JSON retains the exact nested data. All files use the same existing SQLite snapshot and formula-safe CSV rules. Preserve source artifacts, earlier revisions/reviews, unchanged screening counts, and existing output shape when evidence is absent. Reconciliation of screening/study counts does not imply that every study has a verified extraction.

## I6c CLI contract, accepted

Implementation owns the existing review CLI, `tests/test_evidence_cli.py`, and no ledger API changes except bounded defects. Evaluation owns `tests/test_evidence_cli_acceptance.py` and the E6c report. Retrieval owns `docs/verified-evidence.md`, with executable offline guide verification, after its anchor follow-up. Add thin CLI commands in the existing review entry point:

- `attach-source PROJECT RECORD PATH --format txt|jats_xml|pdf --reviewer NAME --reason TEXT`, optional filename/source-url/version-label. Read one byte snapshot and delegate without changing screening. Default filename is the supplied path's basename.
- `documents PROJECT [--record-id RECORD]` returns all source-version metadata. `source-blocks PROJECT DOCUMENT` returns `{"document": metadata, "blocks": exact_blocks}` in one snapshot.
- `propose-evidence PROJECT RECORD --payload FILE --reviewer NAME --reason TEXT` and `revise-evidence PROJECT EVIDENCE --payload FILE --reviewer NAME --reason TEXT` load strict JSON using existing duplicate-key/nonfinite safeguards. Required payload keys: study_id, document_id, field, value, context, anchor. Proposal optionally accepts kind/appraisal; revision optionally accepts appraisal and must reject kind/report/evidence/reviewer/reason overrides. Unknown keys fail; the author/reason come only from named flags. Delegate to frozen APIs.
- `review-evidence PROJECT REVISION --decision confirm|reject --reviewer NAME --reason TEXT` and `adjudicate-evidence` with identical flags.
- `evidence PROJECT [--record-id RECORD] [--verified-only]` returns current rows. `evidence-history PROJECT [--evidence-id EVIDENCE]` returns `{"revisions": [...], "reviews": [...]}` in one snapshot.

Keep --db before the command, JSON stdout and nonzero contextual stderr errors. Independent CLI acceptance includes a complete synthetic finding/appraisal workflow, independent confirmation, edited/stale exclusions from verified files, payload/ownership rollback, source deletion/reopen and dependency isolation. Update README plus an executable offline guide. No automatic findings, clinical tool choice, source download or model calls.

`list_documents(project_id, record_id=None) -> list[dict]` returns all versions in creation order; active means latest attachment for each report. Validate project/optional record. `get_document_bytes(project_id, document_id) -> bytes` and `get_source_blocks(project_id, document_id) -> list[dict]` reject unknown/cross-project IDs and check stored source/block hashes before returning. Public reads do not require reparsing PDF or source files. Canonical block hashing is finite, sorted-key, compact UTF-8 JSON; immutable parser identity and hashes describe the stored representation. Opening old ledgers creates tables compatibly but no document data or new count meanings.

Export document metadata, all version-specific blocks, and exact source bytes in the same existing SQLite snapshot. When documents exist, project.json adds `documents`, `source_blocks` rows carrying document ID plus each block, and `document_artifacts` manifest (`document_id`, `sha256`, `size_bytes`, `export_file`). Add `documents.csv`, `source_blocks.json`, and source bytes under `documents/<document_id>/<filename>`; include these paths in result.files. Check stored hashes before output replacement. Preserve all older source versions, PubMed assets, linkage arrays, generic nine-file shape when no optional data, and unchanged counts. Repeated unchanged exports are byte deterministic. An external actor consistently rewriting all SQLite data/hashes is outside unsigned-ledger integrity guarantees.

E6a independently verifies synthetic TXT/JATS/PDF exact blocks/typed locators/hash truth, Unicode and nested text, table/cell separators, duplicate prevention/reference exclusion, actual PDF page positions including blank pages, single byte snapshot, new active versions/reopen/source deletion, project isolation/input/parse failures without partial rows, stored byte/block corruption rejecting reads/export, deterministic manifests/JSON/CSV, no model/network initialization, and a second writer during snapshot export. Verify acquired real JATS sources parse with valid source paths; do not label them as synthetic or infer clinical findings. Freeze the later extraction API after this source gate.
