# Source-anchored evidence milestone: coordinator draft

Status: draft for the gate after study linkage. Do not implement before coordinator freezes individual tickets. This gate stores human-entered structured findings and appraisal judgments with verifiable source quotations. It does not infer clinical findings, pool effects, score risk of bias automatically, or treat a citation label as evidence support.

## Architecture decisions

Keep source parsing/version storage in `src/review/documents.py` and extraction/reviewer state in `src/review/evidence.py`; ReviewStore exposes their public APIs. Source bytes are durable SQLite artifacts, not filesystem pointers. Parsed source blocks carry stable version-specific IDs and typed locators: actual one-based PDF positions, XML paragraph/table paths, or plain-text blocks. XML paragraphs must never be labeled PDF pages. Retain parser identity/version and exact source hash, alongside canonical block text and character offsets.

Supported source adapters will be frozen separately: UTF-8 text and publisher article XML use the standard library; PDF extraction lazily uses the existing PyMuPDF dependency. No model/settings/dotenv/network initialization. Every source attachment is a new immutable version with reviewer/reason; old bytes/blocks remain retained. Replacing a report's active document makes earlier extraction verification stale until a new revision is anchored to the new version and independently checked.

Source parsing must be deterministic from the very same byte snapshot that is hashed/stored. Quote anchors identify document/version/block, half-open character offsets, and the exact substring. Validate nonempty exact quotation against canonical block text, bounds, and matching report/project. Preserve table/section locators and describe text normalization; automatic quote validation proves location, not entailment of the value.

## Structured extraction and verification

Each manual extraction has a stable ID and append-only proposal revisions. Its current revision identifies report, linked study, active source version, field, finite JSON value, context (population, comparison, outcome, timepoint, analysis, units and notes as applicable), source anchor, author and reason. A revision can correct values/context/anchors and always invalidates earlier verification. Report/study ownership and current full-text inclusion are checked; conflicted/missing study links cannot supply a verified study-level result.

For design-appropriate appraisal, use a separate explicit extraction kind with user-selected instrument name/version and domain. Preserve the domain judgment and supporting quotation/reason; instrument choice and application remain review-protocol inputs. Do not silently substitute an appraisal tool or compute an overall quality score. This supports auditable judgments without claiming a validated automated appraisal system.

Verification is append-only and refers to an exact current revision ID. A distinct reviewer can confirm or reject it with a reason. Latest vote per verifier determines agreement/conflict; no majority vote or automatic union. An explicit adjudication can resolve existing verification reviews with a named reviewer/reason, and subsequent reviews invalidate it. The current revision's author cannot confirm/adjudicate their own proposal. Source changes or proposal revisions prevent an earlier confirmation from certifying new content.

Current states must distinguish proposal, confirmed, rejected, conflict, stale source, and no longer eligible/linked. Verified exports contain only current confirmed revisions with valid source/eligibility/linkage dependencies; proposals and unresolved/rejected/stale content remain visible in audit exports. Source quotation support still requires reviewer judgment. Duplicate extraction slots and cross-report disagreement must remain visible rather than being silently pooled or merged.

## Acceptance before CLI

Use independently authored synthetic source bytes, quotations, values, context and revision truth. Prove source hashes/blocks/quotes after original-file deletion; invalid quote offsets/text/version/report/project reject atomically; independent confirmation, rejection/conflict/adjudication and later-vote invalidation; proposal edits and document replacements invalidate verification; current exclusion or missing/conflicting study links suppress verified export. Confirm exact JSON/CSV provenance, deterministic source/evidence exports, preserved history, and one SQLite snapshot during concurrent source/evidence revision. Existing generic/PubMed/linkage gates remain green.

The real licensed medical corpus will then exercise the same source locator interface and independently checked retrieval anchors. Coordinator will review quantitative/population/timepoint/negation failures before selecting a retrieval default. End-to-end acceptance runs one temporary review through imports, report/study screening and linkage, source attachment, manual extraction/verification, reconciled counts and verified evidence export, without network or Agnes calls.

## I6a source-document contract, queued after the study milestone

Implementation owns `src/review/documents.py`, necessary ReviewStore/exporter delegations, and `tests/test_review_documents.py`. Retrieval supplies independent synthetic source fixtures and metadata under `tests/fixtures/evidence/`; Evaluation owns `tests/test_review_documents_acceptance.py`. No evidence proposals, verification, or CLI in this first source ticket.

`parse_source_bytes(content, format) -> {"parser_id": str, "parser_metadata": dict, "blocks": list}` accepts nonempty bytes and exactly `txt`, `jats_xml`, or `pdf`. Parse the supplied bytes once without file calls; failures are contextual ValueError and leave no ledger data. Parser identity is versioned per format (`lit-rev-engine.source.v1.txt`, `.jats_xml`, `.pdf`); parser_metadata records Python version plus effective decoding/normalization/extraction options, and PyMuPDF version for PDF. TXT decodes UTF-8/BOM and retains exact decoded text as one block with ID `text:1`, locator `{"type":"text_block","ordinal":1}`. Reject empty/whitespace-only source content.

Frozen parser_metadata keys: all formats include `python_version` from the current interpreter. TXT adds `encoding="utf-8-sig"` and `normalization="none"`. JATS adds `normalization="xml-whitespace-v1"`, `tables="rows-tab-separated-v1"`, `external_dtd="ignored"`, and `entities="rejected"`. PDF adds `pymupdf_version` (PyMuPDF VersionBind), `sort=true`, and `normalization="none"`. Runtime version values are captured provenance, not hard-coded benchmark assumptions.

PDF uses lazy PyMuPDF from bytes and sorted page text, one block for each actual PDF page (including blank pages), ID `pdf:page:N`, locator `{"type":"pdf_page","page":N}`. Do not run RAG settings, chunking, or models. Reject corrupt/encrypted/unreadable/all-text-empty documents; no OCR or password guessing. Report one-based PDF positions, not printed journal page numbers. Canonical PDF block text is the extracted text, without further whitespace rewriting.

JATS XML requires article root; reject declared entities/error/malformed XML and make no external DTD/network calls. Extract article-title, abstract/body paragraphs, and complete body table-wrap blocks in document order. Skip selected table descendants as standalone paragraphs to avoid duplicating table content. Do not index reference lists as findings. Stable IDs are `xml:` plus a structural path of local tag names with one-based sibling indices, e.g. `/article[1]/body[1]/sec[1]/p[1]`. Locator fields are `type="xml_element"`, `path`, `tag`, optional original `element_id`, `section_title` (nearest enclosing section title), and `table_label`. Canonical mixed paragraph text collapses whitespace after concatenating inline text, preserving meaningful punctuation/Unicode. Table text consists of nonempty lines for label, caption, every table row (cells separated by tabs), then table-wrap-foot text; lines are separated by newlines. Cell/caption/foot text uses the same inline whitespace normalization. It does not infer values from images or spanning-cell semantics. Document the transformation and retain exact XML bytes. Every block has `id`, one-based `ordinal`, `text`, and `locator`; IDs are unique within a document version. Require at least one nonempty extractable block.

`ReviewStore.attach_document(project_id, record_id, content, format, reviewer, reason, *, filename=None, source_url="", version_label="") -> dict` creates a new immutable source version for an existing report, independent of screening status. Nonempty reviewer/reason required. Filename defaults to source.txt/source.xml/source.pdf, and must be a safe single basename (no separators, traversal, or control characters); URL/version label are retained strings and never fetched/inferred. Parse/hash/store the same bytes transactionally. Return metadata `id`, `project_id`, `record_id`, integer `version` (per-report creation sequence, not a publisher version), `format`, `filename`, `source_url`, `version_label`, `source_sha256`, `size_bytes`, `parser_id`, `parser_metadata`, `blocks_sha256`, `block_count`, `reviewer`, `reason`, `created_at`, `active=true`. Repeated attachment makes a new version even for identical bytes; it is an explicit provenance revision, not a keyed import.

`list_documents(project_id, record_id=None) -> list[dict]` returns all versions in creation order; active means latest attachment for each report. Validate project/optional record. `get_document_bytes(project_id, document_id) -> bytes` and `get_source_blocks(project_id, document_id) -> list[dict]` reject unknown/cross-project IDs and check stored source/block hashes before returning. Public reads do not require reparsing PDF or source files. Canonical block hashing is finite, sorted-key, compact UTF-8 JSON; immutable parser identity and hashes describe the stored representation. Opening old ledgers creates tables compatibly but no document data or new count meanings.

Export document metadata, all version-specific blocks, and exact source bytes in the same existing SQLite snapshot. When documents exist, project.json adds `documents`, `source_blocks` rows carrying document ID plus each block, and `document_artifacts` manifest (`document_id`, `sha256`, `size_bytes`, `export_file`). Add `documents.csv`, `source_blocks.json`, and source bytes under `documents/<document_id>/<filename>`; include these paths in result.files. Check stored hashes before output replacement. Preserve all older source versions, PubMed assets, linkage arrays, generic nine-file shape when no optional data, and unchanged counts. Repeated unchanged exports are byte deterministic. An external actor consistently rewriting all SQLite data/hashes is outside unsigned-ledger integrity guarantees.

E6a independently verifies synthetic TXT/JATS/PDF exact blocks/typed locators/hash truth, Unicode and nested text, table/cell separators, duplicate prevention/reference exclusion, actual PDF page positions including blank pages, single byte snapshot, new active versions/reopen/source deletion, project isolation/input/parse failures without partial rows, stored byte/block corruption rejecting reads/export, deterministic manifests/JSON/CSV, no model/network initialization, and a second writer during snapshot export. Verify acquired real JATS sources parse with valid source paths; do not label them as synthetic or infer clinical findings. Freeze the later extraction API after this source gate.
