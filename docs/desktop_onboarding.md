# Desktop onboarding checkpoint

This extends the existing production UI and native packaging on `codex/desktop-distribution`. Candidate version: **0.3.0-desktop-beta.2**, native build **3002**. It is private and does not replace the published source beta or earlier immutable native candidates. The exact clean source SHA and rebuilt artifact hashes belong in the external candidate packet.

## Entry and return

A new managed-desktop profile with no research workspaces opens Welcome. **Try the saved example** explicitly creates the existing thirty-paper public example workspace and saved search/map. It does not run a live search, preparation, indexing or inference. **Set up my research workspace** opens the existing Settings components in Sources, Retrieval and AI steps; each offers **Set up later**. The summary reads existing capability and operation receipts. Saving configuration is distinct from testing it.

Existing desktop workspaces and direct research-task links are not interrupted. **Help & setup** reopens the guide. Opaque task IDs and existing draft-save barriers preserve the originating comparison/cell; no research text or credential is added to URLs. Completing the guide records progress, not scientific review or optional-model readiness.

## Persistence and boundaries

The existing private, session-owned runtime-settings record has one optional `onboarding` envelope. Its independent revision protects two-window updates; configuration and onboarding writes preserve one another. Completion is sticky. Legacy configuration remains readable and an onboarding-only write does not activate unsaved defaults or replace operator configuration. Malformed progress is reported without disabling valid Core settings. There is no second research database, provider adapter or credential store.

Progress contains only schema/revision/step/completed. Provider keys and test/consent receipts retain their existing session-only lifetime; restarting the backend clears them. Research data stays in the existing dedicated native data directory. Browser-beta, Track B and preview data are not scanned or migrated. Storage/cookie loss still has the recovery limitations documented in [desktop distribution](desktop_distribution.md).

## Honest optional status

Entered settings or a present key mean setup is still required until an explicit existing connection test succeeds. Installed model files and installed libraries are distinct from a recorded runtime check. Runtime checked requires both encoder and reranker execution on the selected device. Source indexing remains task-specific and explicit. Failed or missing optional setup does not change pinned research profiles or silently fall back; Core can be explicitly selected for new manual work.

The final summary performs metadata reads only. No save, skip, navigation or summary starts provider connectivity, model installation, source preparation, indexing, search or inference. The native optional-library installer remains separate from model weights; Windows optional runtime remains unavailable rather than being labeled Ready.

## Acceptance boundaries

Fresh automated evidence includes onboarding storage/CAS/session isolation, strict desktop gating, no credential/research export leakage, saved-example retry IDs, setup interruption/return, dirty-settings barriers and observed-status labeling. New installer notice inputs are verified and copied before payload signing/inventory. See [native obligations](native_distribution_obligations.md).

Automated or cross-build success is not installed Windows acceptance, browser-downloaded Mac trust acceptance, model quality or human usefulness validation. Actual new-artifact checks, signing availability, failures and skips are recorded separately in the candidate's external evaluation packet. Earlier native observations remain historical in [desktop distribution evaluation](desktop_distribution_evaluation.md).
