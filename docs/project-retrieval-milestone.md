## Scope and interface

Use the accepted ledger source blocks, not filesystem pointers or a user's live Chroma collection. Retrieve only a project's active document versions, with one SQLite read snapshot. Frozen API: `ReviewStore.search_sources(project_id, query, *, top_k=5, method="bm25", scope="included")`. Scope `included` uses current full-text inclusions; explicit `all_attached` supports inspecting sources during screening. Resolved study linkage is reported as provenance rather than inferred from report identity. Unknown project, blank query, invalid options, corrupt selected source bytes/blocks or a selected source's explicit DOI/PMID contradiction with the current canonical report fail without ledger mutations. top_k is a positive integer, rejecting booleans, without an arbitrary cap.

CLI: `retrieve-sources PROJECT --query TEXT [--top-k N] [--method token_overlap|bm25] [--scope included|all_attached]`, with --db before the command and existing JSON stdout/error behavior. Stdout is the retrieval trace and can be saved explicitly by the caller; this command creates no ledger search/evidence events and has no --output flag. BM25 is the selected software default following the frozen development comparison; it failed the prospective held-out medical-quality gate.

Return a deterministic JSON object identifying query, scope, method/version/parameters, selected source-document manifest and ranked candidate passages. Each passage retains document/report IDs, source/block hashes, parser identity, original block ID, exact Unicode character bounds, text, typed locator, score/rank and current screening/linkage state. A passage's text must equal the exact canonical-block substring at its half-open bounds. Document and snapshot provenance must survive export/reopening. These are passage candidates, not answers or verified findings; callers still propose and independently verify an extraction.

## Candidate preparation, fixed before ranking

Use at most 200 whitespace-delimited words per window, with 40 words of overlap. Word boundaries come from `\S+` matches; each window spans from its first word's original character start to its last word's original end. Preserve the complete original substring between those bounds, skip whitespace-only blocks, and never join blocks. A shorter final window is retained only if it adds words beyond the prior window. Order ties by report creation order, block ordinal, start, then end.

Tokenization is Unicode `\w+` after casefolding, without stemming or synonym expansion, version `unicode-casefold-word-v1`. Remove exactly: a, an, and, are, as, at, be, been, by, did, do, does, for, from, had, has, have, how, in, is, it, its, of, on, or, that, the, their, there, these, this, to, was, were, what, when, where, which, who, with, would. Preserve negation and numeric terms. Use sorted distinct query tokens for deterministic floating-point accumulation. Empty effective token sets return no matches, but retain the selected source manifest/indexed-passages count and still validate selected source integrity.

Token overlap scores the count of distinct query tokens present in each window. BM25 uses k1=1.2, b=0.75 and `idf=log(1+(N-df+0.5)/(df+0.5))`; N and average token length cover all eligible windows in the snapshot. Sum the usual BM25 term-frequency contribution once for each distinct query token. Return only positive-score windows, at most top_k; never interpret that score as probability or support confidence. No answerability threshold is inferred from this ranking.

The result has schema_version=1, status=candidate_passages, project_id, exact original query, method, method_version (`lit-rev-engine.project-retrieval.v1.<method>`), parameters, scope, top_k, source_manifest, source_snapshot_sha256, indexed_passages, matched_passages, and passages. Parameters retain tokenizer ID, sorted stop-word list, window_words=200, overlap_words=40, plus k1/b for BM25. Source manifest rows contain document_id, record_id, version, format, source_sha256, blocks_sha256, parser_id, parser_metadata, source_identifiers, source_url, version_label, record_title, doi, pmid, title_abstract_state, full_text_status, full_text_state, study_link_state, and study_ids. Hash the complete source manifest using compact sorted-key finite UTF-8 JSON. Each result passage contains rank, score, project_id, record_id, document_id, document_version, source_sha256, blocks_sha256, parser_id, anchor, locator, full_text_state, study_link_state, and study_ids. Anchor is exactly block_id/start/end/quote, directly usable by propose_evidence with its document/report IDs; locator is separate. State and linkage metadata describe the current snapshot, not extraction verification.

Metrics will treat OR sufficient-support sets as alternatives, and AND passages within one set as required together. A passage requirement is covered only when every question-specific gold quote for that passage is fully contained in returned exact windows for that same source/block; separate windows may cover separate quotes. Support coverage is the maximum covered fraction over alternative sets, averaged over answerable questions. Complete support means at least one full set covered. Hit/MRR identify the first rank containing any required gold quote, and no-answer questions are excluded from these answerable denominators. Report nonempty-candidate rate and retrieved limitation/context spans separately for no-answer queries; candidates never constitute answers.

Each split has seven answerable and two no-answer questions. A development candidate is eligible when mean best-alternative support coverage at five is at least 0.75 and at least four of seven questions have complete support at five. Choose among eligible candidates by support coverage, then complete-question count, then mean reciprocal rank at five; an exact tie favors BM25. If no candidate passes, stop before held-out ranking and assign a new development-only ticket. The selected default must independently satisfy the same held-out coverage/completeness thresholds, plus 100% anchor validity and operational isolation. These modest pilot thresholds do not establish clinical quality. Do not tune on held-out failures or rewrite frozen gold to improve metrics.
