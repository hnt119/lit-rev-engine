## Minimal Windows affected-check inclusion

The published baseline Windows browser opens the 30-paper saved example, prepares three papers, creates **three** fields/nine cells, checks three same-paper cells, passage round trip, drafts, export, restart and replacement. That historical coverage does not establish the new search-design concepts/diagnostic meanings, typed dimensions or saved views. Its original production HTTP helper also uses a three-by-three board.

A new portable `tests/workbench/browser_workbench.cjs` and its invocation in `tests/windows/run_source_acceptance.py` are **prepared, not Windows-executed** for this checkpoint. They use a separate browser profile/workspace on the same production service and retain the original nine-cell regression. The proposed journey includes exact manual strategy/notes export, a three-paper/five-field table, source inspection, typed unreviewed multi-values, saved view/filter/export, passage return, drafts, refresh and restart/replacement verification. Record the actual completed substeps after running it; do not infer missing-information or scientific correctness from the selected full-text reports. Independent API fixtures cover full/abstract/unavailable scopes, history, conflicts and ownership. Browser tests must wait for acknowledged drafts and visible results.

Normal source CI remains Core/offline. Do not enable `--models`, provider diagnostics or competitor access for a display/filter change. Real optional-model and live PubMed evidence remains separately labeled with exact source and authorization. Windows runner checks are not physical Windows 11 consumer-installation evidence; source ZIP remains setup-required, not a native installer.
