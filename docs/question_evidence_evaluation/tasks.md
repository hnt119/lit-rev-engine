# Participant tasks and field definitions

Status: proposed tasks; question, documents, definitions and answers are **not locked**. Use a bounded real question the participant understands. Preserve unresolved population, cohort, specimen and outcome definitions; do not inherit gut-only or mandatory diet/exposome constraints.

## Task 1 — search design

Create a defensible PubMed strategy for the approved question. Explain the required concepts, alternatives, preferences, exclusions and criteria deferred to reading. Inspect/edit the exact query, interpret a zero-result or provider-warning example, perform only authorized diagnostics, explain an established seed's query membership separately from capped-preview recovery, deliberately execute/import the allowed result set, then reopen and export the strategy.

The neutral task description must not tell participants which terms or UI buttons produce the answer. Record original text, exact saved variants, edits, warnings, unapproved scope changes, assistance and unresolved issues. A real information specialist or supervisor reviews terminology, Boolean logic, mapping and limits; an automated lint panel is not PRESS approval. Other database execution is an external strategy/import record, not a validated PubMed translation.

Use locked development seeds for iteration and a separately withheld test set after the query is locked. Existing development examples cannot become independent validation by relabeling them. No provider access means membership is NOT_RUN/unresolved, not absent.

## Task 2 — three reports × five fields

Using the same approved available original documents in every condition, produce 15 checked cells, locate the defined subgroup in a saved view, correct one deliberately ambiguous/mistaken value through the original source, revise it explicitly, export the full table and current view, and reopen the same view/draft. Ambiguity or a seeded software mistake must be disclosed as a task manipulation, not a real scientific finding.

Proposed five fields, subject to approval before reading results:

| Stable field ID | Definition to lock | Scope and evidence requirement |
| --- | --- | --- |
| population | Reported participants/cohorts, including separate groups when present | Record recruitment population separately from reported ethnicity/ancestry. Do not infer identity from country or author affiliation. |
| setting | Recruitment setting/geography | Use exact reported setting and cohort scope; unspecified is unknown. |
| specimen | Microbiome specimen/sample sites | Multi-valued; distinguish specimens across cohorts or observations. No gut default. |
| methods | Study design and the agreed key sampling/measurement method | Definitions specify desired detail; no universal quality score or design hierarchy. |
| focus | Reported outcome domain/research focus relevant to the task | Preserve outcome-to-cohort linkage where explicit. A report mentioning two tags does not establish their relationship. |

The task must include an actual multi-cohort or multi-site report and an insufficient-information case. If explicit scope linkage is absent, a correct outcome may be “report mentions both; relationship not established.” An unknown/missing answer with an honest inspected scope can be correct; do not reward fabricated completeness. A source-matching quotation is not enough: adjudication checks support and applicability.

Record field definitions and source manifests before comparator use. Keep proposals, draft-only notes, reviewed submissions, self-declared support and independent adjudication separate. The ordinary app path remains read/select excerpt → comment/judge → review/save; navigation must not run retrieval or make scientific decisions.
