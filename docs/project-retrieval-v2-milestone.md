## Candidate and stable interfaces

Add only `method="bm25_context"` to the existing `ReviewStore.search_sources` API and `retrieve-sources --method` choices. Preserve the v1 methods, default `bm25`, result fields, scopes, snapshots, exact own-block anchors, source integrity/identity checks and no-ledger-write behavior. The candidate ID is `lit-rev-engine.project-retrieval.v2.bm25_context`. No settings/models/network/clinical-term dictionaries, result-heading boosts, article/question/answer hardcoding or automatic findings.

Retain v1 Unicode tokenization, exact stop words, sorted distinct query tokens, 200-word windows with 40-word overlap, k1=1.2, b=0.75, IDF formula, positive filtering and deterministic tie order. For each XML paragraph/table window, find at most one nearest preceding accepted paragraph block whose locator has the exact same immediate structural parent path. Compute that parent by removing the final path segment. A target cannot borrow from itself. Only `jats_xml` targets with `locator.type="xml_element"` and `tag` p/table-wrap are eligible; a context must have tag p. Different parent, document, report, project or source version cannot contribute. TXT, PDF, titles and targets without preceding eligible paragraphs have empty context.

The context is the last at most **80** whitespace-delimited words of the preceding paragraph, using its original first/last word character bounds and exact substring. No reparsing, joining blocks into a purported quotation, normalization or context inference. Each scoring representation concatenates the own-window tokens and context tokens once, preserving their term frequencies. BM25 document lengths, DF, N and average length use these augmented representations for every selected window; query terms still contribute once each.

New method parameters add `context_rule="preceding-paragraph-same-xml-parent-v1"` and `context_max_words=80` to the existing BM25 parameters. Each new-method passage adds `scoring_context`, an empty list or one object containing `anchor` (exact block_id/start/end/quote) and that block's exact `locator`. The context shares the passage's document/source/block hashes and parser identity. V1 method traces acquire no extra fields. Metrics and evidence proposal reuse use **only the own-block anchor**; context quotes cannot count as returned finding support. Report contexts separately so a reviewer can inspect why an otherwise weak lexical match ranked highly.

Implementation owns src/review/retrieval.py, necessary CLI changes and tests/test_project_retrieval.py. Synthetic gates must independently check augmented BM25 math, exact 80-word suffix, closest preceding paragraph, immediate-parent isolation, target/format exclusions, empty context, all selected integrity/snapshot guarantees and unchanged v1 traces. Do not read new held-out gold or run medical ranking. Root alone changes the selected default after evaluation review.
