# Local beta 0.3.0-beta.1 — local publication checklist

This checklist does not authorize tagging, uploading, publishing, portfolio
merging/deployment, paid services or private-data upload.

- Confirm the reviewed Track A branch and exact full source SHA. Keep Track B,
  main, original databases, old frozen `.2` artifacts and the actual portfolio
  checkout unchanged.
- Recheck remote tag/release collision immediately before approved publication.
- Review the source diff, mandatory exact MIT license, required notices, source
  rights and all package metadata. Do not substitute another license.
- Build from a clean checkout of the exact reviewed commit into a fresh external
  directory using `scripts/build_local_preview.py --expected-source-commit SHA`.
- Independently audit the ZIP against that commit, manifest and SHA256SUMS;
  inspect every payload path, public-source attribution and forbidden private/
  runtime/model material. Record generated `RELEASE.json` source SHA.
- Exercise the extracted package with fresh isolated data: setup, production
  startup, comparison → passage search → exact source → return to cell, draft
  retention, refresh/reopening, shutdown/restart and CSV/JSON exports.
- Test optional capabilities from the extracted ZIP and record mocks, real
  embeddings and live-provider/model checks separately, including failures,
  skips, actual usage and evidence limitations. Do not make quality claims from
  software checks.
- Record the final source commit URL, asset names/bytes/SHA256 values, exact
  validation outcomes and any release blocker in the final validation report.
- Bind the prepared website overlay only to those verified final MIT assets;
  its read-only saved-results demo must make no API/model calls. Keep installation
  and license actions accurate. Never invent a hosted download URL.
- Obtain the owner’s final publication approval for the exact commit/assets,
  proposed tag `v0.3.0-beta.1`, GitHub prerelease and separate portfolio changes.
- Only after approval, publish the purpose-built ZIP, matching manifest and
  SHA256SUMS as the prerelease assets; do not upload an earlier working-tree
  archive or reuse previous hashes.

Supported-platform wording must remain: macOS arm64 tested; Linux installation
unverified; Windows unsupported; setup required; models optional; documented
cookie/access and force-stop recovery limitations.
