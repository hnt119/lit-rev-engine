## What changed

Research & AI Settings separates research sources, optional AI and privacy/usage from per-search scientific specifications. Defaults prefill new drafts without changing retained searches. Session-owned keys stay in backend memory, with presence-only responses and clearing/re-entry after restart. Two-tab settings edits use explicit revision conflicts/rebase and research navigation preserves drafts.

Optional local/OpenAI/DeepSeek adapters are real backend transports. There is one configured provider, fixed approved destinations, provider-specific bounded JSON requests, no redirect/retry/fallback, exact one-run data/cost consent and existing application/source validation. Suggestions never automatically attach evidence, set support/verification or submit. Explicit Use in draft can copy validated references; inspection and human support remain unassessed. Core saved/manual research remains model-free. These adapters have offline/mock validation; actual account/model compatibility is not live-verified.

The separate Electron prototype wraps the unchanged production Next/FastAPI UI and engine. It includes verified Electron/Node and standalone Python runtimes, isolates research data outside the app and verifies owned services before showing the window. It does not bundle optional weights/ML packages or replace the browser beta.
