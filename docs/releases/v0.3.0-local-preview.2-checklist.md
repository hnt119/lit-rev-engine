# Local publication checklist — v0.3.0-local-preview.2

This is a checklist/template, **not permission to run publishing commands**.
Keep the exact source SHA, generated assets and observed checks together. Fill
the local copy from the final `RELEASE.json`, manifest, SHA256SUMS and fresh
validation reports; do not amend the source commit merely to add its own hash.

## Source and distribution gate

- [ ] Record the full reviewed commit SHA and committed source URL.
- [ ] Confirm the feature branch contains that commit and main is unchanged.
- [ ] Audit the final staged/committed file list: no credentials, cookies,
  private research state, personal absolute paths, runtime/cache artifacts,
  model weights, backup archives or old generated preview assets.
- [ ] Resolve the missing project-code license/distribution terms with the
  owner. **Currently blocked; no license is selected.** Retain all required
  public-paper attribution and dependency/model provenance notices.

## Exact-commit build and fresh checks

- [ ] Use a clean checkout of the recorded SHA, with no borrowed untracked app
  files or existing research data. Build the purpose-made distribution from it.
- [ ] Verify `RELEASE.json` says that exact SHA and a clean committed checkout.
- [ ] Verify every archive member, manifest entry and both SHA256SUMS lines.
- [ ] Independently rebuild and compare ZIP bytes.
- [ ] Extract into an empty folder; run setup with pinned prerequisites.
- [ ] Start the production app using a new external temporary data directory.
- [ ] Exercise board → passage search → exact source → cell return, scoped
  drafts, explicit submission/exports and controlled restart/reopening.
- [ ] Record actual browser checks separately from API/unit/software checks.
- [ ] Record fresh failures/skips and supported platforms honestly. Preserve
  historical results separately; do not sum overlapping test suites.
- [ ] Confirm all original research data and actual portfolio files unchanged.
- [ ] Record the final ZIP, manifest and checksum-file SHA-256 values in the
  local validation report. The checksum file itself is not self-hashed.

## Local overlay readiness

- [ ] Bind only the verified final assets into a new prepared overlay output.
  Confirm its relative download links resolve to actual matching bytes.
- [ ] Validate the isolated static export. Keep the real portfolio unchanged.
- [ ] Do not commit a generated ZIP/hash into the source commit from which that
  same ZIP is built. Do not insert a speculative hosted/GitHub download URL.

## STOP — separate approval required

- [ ] Obtain explicit approval for the exact tag target, final three assets,
  release notes, resolved distribution terms and **pre-release** publication.
- [ ] Only after approval, create/push `v0.3.0-local-preview.2` at the recorded
  SHA. Never replace an existing tag silently or force-push it.
- [ ] Create a GitHub pre-release and upload only the three verified assets.
- [ ] Verify published download bytes/checksums and record the actual URLs.
- [ ] Obtain separate approval before applying/publishing the portfolio overlay.

No steps in this last section are executed during the current preparation.
