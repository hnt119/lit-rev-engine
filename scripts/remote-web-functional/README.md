# Remote web functional acceptance candidate, CSV augmentation

SOURCE-ONLY, UNEXECUTED, REQUIRES INDEPENDENT REVIEW. Source is bound to `a54cd9acc9cca860acc0e2aabcee01f9329276c4` and infrastructure to the exact reviewed PR head. The integration owner controls copying `remote-web-functional.yml` to `.github/workflows/remote-web-functional.yml` and the remaining five files to `scripts/remote-web-functional/`, publication and the single authorized run. No workflow has been installed or dispatched by authoring this candidate.

The sole trigger is `pull_request` `opened`, guarded to the public repository, same-repository `codex/remote-web-functional` head and default base. It checks out the PR head explicitly, not GitHub's merge SHA. It does not run on PR updates or retry automatically. Existing PRs are untouched. Standard Ubuntu has one job and a 30-minute limit including setup.

The job installs pinned `playwright-core` 1.62.1 and pnpm 10.20.0, the source's pinned Python web requirements and frozen web lock, and builds the source. It does not install a browser, model or application provider. Setup failure prevents the journey and may leave no receipt. Unsupported Chrome or kernel prerequisites block the run; there is no sandbox weakening.

Fresh private HOME, data, temporary directories and browser profile support this narrow initial Core smoke. The real preinstalled Chrome uses Playwright pipe and its native sandbox. `chrome://sandbox` namespace and seccomp reports and actual renderer namespace and extra-filter evidence are mandatory. The real native diagnostic confirm must produce Cancel and Confirm. In the actual app, choosing an unparsed disposable citation file, attempting to switch panes, and using the application's own discard guard must demonstrate Cancel retains the file and Confirm clears it; no import POST may occur. The fixed receipt records the actual passed gate booleans, renderer count and Chrome version, with no process arguments, PIDs or browser data.

The source-assisted UI journey creates `Remote functional software QA` offline, selects three public saved-example papers, prepares them, creates a three-field board, inspects and attaches a source excerpt, autosaves a draft, refreshes, submits a reviewed entry and downloads the actual board JSON and CSV. It stops and restarts the owned `run_web.py` launcher with the same disposable data, reopens through the same owned browser profile, and downloads both again. An independent Python process parses all four exports, reconstructs the exact public source using the application's saved-example adapter, checks paper/field/revision/inspection and Unicode ranges, and compares every CSV field and row with the closed JSON table, including the submitted and untouched cells. It checks formula escaping and nested JSON values, and rejects duplicate JSON keys, malformed or ragged CSV and unexpected headers. It is independent of the export serializer but shares the application's source adapter; it is not independent scientific verification. At this source the board export has no export-time timestamp and is deterministic (`src/mvp/evidence_board.py`, `export`).

No artifact, cache or shared-storage upload is used. A completed run rechecks tracked source cleanliness after cleanup, then an independent Python process repeats the public audit readback. Its closed validation checks the full main board-audit shape, exact fixture paper metadata and canonical source excerpts, the fixed QA text, and bound IDs, references, timestamps and hashes. Unknown keys and arbitrary string values are rejected. It fails closed if this exact narrow audit shape changes. Untracked build output is separate from the tracked-source check and is not published.

Only after those gates pass, the validator emits one bounded bundle in the job log. It includes the fixed receipt, four actual before/after public-fixture JSON and CSV exports and the fixed readback receipt, each encoded as base64 file bytes in canonical JSON with schema `remote-functional-bundle-v1`. The JSON is gzip-compressed with `mtime=0`; compressed size must not exceed 1 MiB. The fixed `REMOTE_FUNCTIONAL_BUNDLE_V1 BEGIN` line carries compressed/uncompressed sizes, both SHA-256 digests and chunk count; ordered `REMOTE_FUNCTIONAL_BUNDLE_CHUNK i/n` lines carry at most 4096 base64 characters each; the fixed `REMOTE_FUNCTIONAL_BUNDLE_V1 END` closes it. A verifier can join chunks in order, base64-decode, check the compressed digest and size, gunzip, check the raw digest and size, decode the six named files, verify their receipt hashes, and rerun `readback.py` against the exact clean source and public fixture. Failure emits only `REMOTE_FUNCTIONAL_NO_BUNDLE`. Profile, database, auth, environment, exceptions and raw logs never enter this evidence bundle. Setup output is suppressed. GitHub Actions logs are not billed as artifact storage; no shared artifact quota is assumed.

The receipt binds infrastructure and source identity, build ID, public fixture tree and manifest, Chrome executable, runner image/kernel, dependency locks and observed gates. FAILED identifies an unexpected UI/readback/harness failure needing triage; BLOCKED identifies a missing prerequisite, security gate or cleanup. Neither implies an application defect by itself. Downstream stages remain NOT_RUN.

Back/forward, keyboard and narrow layout, two-tab conflicts and rejected-save retention, unavailable/missing evidence, optional models, investigations/PR #25 and the full coverage matrix are explicitly NOT_RUN. Native installation, human usefulness and scientific validity are not established. Source review establishes no runtime success.
